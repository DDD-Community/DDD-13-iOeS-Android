## 1. 커밋별 현상 → 처리결과

### 1-1. `9819651` 마이페이지 아바타

- **현상**: 마이페이지 아바타 자리에 항상 `Icons.Filled.Person` 플레이스홀더만 표시. 서버가 `MyPageHome.profileImageUrl`을 내려줘도 반영되지 않음.
- **처리**: `home.profileImageUrl`이 non-null && non-blank면 Coil `AsyncImage`(`ContentScale.Crop`, `fillMaxSize`)로 렌더, 아니면 기존 Person 아이콘 유지.
- **부가 사실**: URL 정규화는 상류(`UserMapper`, `AuthMapper`)에서 이미 `takeIf { it.isNotBlank() }`로 blank→null 처리됨. 화면 쪽 `isNullOrBlank()`는 이중 방어.
- **리스크**: 로딩 중/실패 시 플레이스홀더가 없어 원형 영역이 빈 배경으로 노출됨. `AsyncImage`에 `placeholder`/`error`가 지정돼 있지 않음.

### 1-2. `24e8390` 스팟 상세 하단 잘림

- **현상**: targetSdk 35의 edge-to-edge 강제 적용으로, 3버튼 내비게이션 단말(갤럭시 S24 울트라 제보)에서 스팟 상세 최하단 "잘못된 정보가 있나요?" 영역이 내비게이션 바에 가려짐.
- **처리**: 루트 `Column`의 `Modifier`에 `.navigationBarsPadding()` 추가 (기존 `.statusBarsPadding()` 뒤).
- **리스크**: 루트 레벨 패딩이므로 하단 영역 배경색이 내비게이션 바 뒤까지 확장되지 않음(제스처 내비 단말에서 시각적 차이 가능). 다른 화면(스팟 목록/마이페이지 등)에 동일 문제가 남아 있는지는 이번 커밋 범위 밖.

### 1-3. `5a8f113` 스팟 목록 페이지네이션

- **현상 3가지**
  1. 서버가 페이지 경계에서 같은 스팟을 겹쳐 내려주면 `LazyVerticalStaggeredGrid`의 `key = { it.id }`가 중복되어 `IllegalArgumentException` 크래시.
  2. 빠른 스크롤 시 `loadNextPage()` 연타 → 같은 `nextPage`를 중복 요청.
  3. refresh/필터 전환 직후 이전 요청의 늦은 응답이 도착해 stale 데이터가 섞이거나 in-flight 가드가 잘못 해제됨.
- **처리**
  1. `accumulatedIds: MutableSet<String>` 도입, `page.items.filter { accumulatedIds.add(it.id) }`로 신규만 append.
  2. `isLoadingPage` in-flight 가드 — `loadNextPage()`가 `!hasMore || isLoadingPage`면 조기 반환.
  3. `loadGeneration` 세대 카운터 — `refresh()`마다 증가, 응답 처리 직전 `generation != loadGeneration`이면 `return@launch`로 폐기(가드도 건드리지 않음).
- **기존 테스트**: dedup 1건, in-flight 가드 1건 추가됨. **세대(3번)는 테스트 미커버.**
