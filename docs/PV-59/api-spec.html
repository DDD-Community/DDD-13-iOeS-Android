pickflow API — 유저 스팟 공개 시스템 (2026.08.14)

Download OpenAPI specification:

브랜치 2026/HJY/유저스팟_공개시스템_개발에서 신규/변경된 API만 모은 문서다. 전체 배경과 설계 결정은 docs/user-spot-publication-system.md 참고.

이번 브랜치 범위

  • 신규: 나만의 스팟 수정/삭제, 공개 해제(오픈 철회·비공개 전환), 좋아요 등록/취소
  • 동작 변경: 스팟 상세/미리보기/리스트 조회, 저장된 스팟 목록 조회
  • 내부 변경(응답 스펙은 기존과 동일): 오픈 신청, 스팟 검수(승인/반려) — 이력 적재 및 비관적 락 도입

공통 사항

  • 모든 응답은 ApiResponse<T> 래퍼를 사용한다 (success, code, message, data).
  • 인증이 필요한데 토큰이 없거나 무효하면 401 C004, 권한이 없으면 403 C005로 응답한다.
  • 비공개 스팟에 대한 접근은 403이 아닌 404 SP001로 응답해 존재 여부 자체를 숨긴다.

나만의 스팟

사용자가 등록한 스팟의 조회/수정/삭제/오픈신청/공개해제

나만의 스팟 수정

나만보기(DRAFT) 또는 반려(REJECTED) 상태의 스팟을 수정한다. 검수중이거나 공개된 스팟은 SP010으로 응답하므로, 공개를 먼저 해제한 뒤 수정해야 한다. 반려된 스팟은 수정 후 오픈 신청으로 재검수를 요청할 수 있다. 좌표를 변경하면 주소·기상 격자·혼잡 지역과 날씨 정보가 새 위치 기준으로 다시 계산된다 (좌표가 그대로면 외부 API 호출 없이 문구만 갱신). 이미지를 첨부하지 않으면 기존 이미지가 유지되며, 수정으로 스팟 상태가 바뀌지는 않는다.

나만의 스팟 공개 해제 (오픈 신청 철회 / 비공개 전환)

스팟의 공개 상태를 해제해 나만보기(DRAFT)로 되돌린다. 검수중(PENDING)/재검토대기(RE_REVIEW_PENDING)이면 오픈 신청 철회로, 공개(PUBLISHED)면 비공개 전환으로 처리되며 응답의 previousStatus로 어느 쪽이었는지 구분할 수 있다. 이미 쌓인 좋아요/북마크는 그대로 유지된다. 나만보기(DRAFT) 상태는 해제할 대상이 없어 SP009, 철회 직전에 운영자 검수가 확정된 경우에는 SP009 대신 SP004(이미 처리된 신청이에요)로 응답한다. 본인이 등록한 스팟만 해제할 수 있다.

나만의 스팟 오픈 신청 (검수 요청)

오픈 신청 건 승인/반려 (USER_ADMIN 전용)

스팟 검수 (승인/반려)

오픈 신청 건을 승인 또는 반려한다. 승인 시 즉시 지도에 공개되며, 반려 시 사유를 함께 저장한다(기타 사유는 상세 설명 필수). 이미 처리된 건을 다시 처리하려 하면 409(SP004)로 응답한다. USER_ADMIN 권한을 가진 팀원만 접근할 수 있다.
