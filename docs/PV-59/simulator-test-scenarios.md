# [PV-59] 무드 필터 확장 — 에뮬레이터 테스트 시나리오

> 티켓 완료조건을 **에뮬레이터에서 눈으로 확인하는 절차서**다.
> 자동화 테스트(`:app:testDebugUnitTest`)가 이미 커버하는 로직은 여기서 반복하지 않고,
> **실기기에서만 드러나는 것**(실서버 응답, 네비게이션, 실제 렌더)만 다룬다.
>
> 케이스 ID는 완료조건과 1:1이다. 표의 `증적` 칸에 스크린샷 파일명을 적어 PR에 첨부한다.

## 1. 실행 환경 준비

### 1.1 빌드 · 설치

```bash
emulator -avd Pixel_8_API_35 &      # 또는 Medium_Phone_API_35
adb wait-for-device
./gradlew :app:installDebug
```

### 1.2 ⚠️ 패키지명 함정

`namespace`와 `applicationId`가 다르다. **런처에서 아이콘을 누르지 말고 아래 명령으로 띄운다.**

| 항목 | 값 |
|---|---|
| applicationId (설치되는 패키지) | `com.pickflow.app` |
| namespace (클래스 패키지) | `com.pickflow.android` |
| 런처 액티비티 | `com.pickflow.app/com.pickflow.android.app.MainActivity` |

```bash
# 예전에 설치된 com.pickflow.android 가 남아 있으면 반드시 먼저 지운다.
# (구버전이라 무드가 2개만 나와 "적용 안 됐다"고 오판하게 된다 — 실제로 겪은 함정)
adb uninstall com.pickflow.android 2>/dev/null

adb shell am start -n com.pickflow.app/com.pickflow.android.app.MainActivity
```

### 1.3 탐색 화면까지 진입

온보딩 → 로그인 → 비회원 진입 순서다. 로그인 없이 전 시나리오를 수행할 수 있다.

1. 온보딩 **시작하기**
2. 로그인 화면 **비회원으로 시작하기**
3. 위치 권한 팝업 → 허용/거부 무관 (무드 필터와 무관)

### 1.4 네트워크 로그 켜두기

무드 필터의 핵심 회귀(HTTP 400)는 **화면에 안 보인다.** 반드시 로그를 함께 본다.

```bash
adb logcat -c    # 시나리오 시작 전 비우기

# 시나리오 수행 후
adb logcat -d | grep -oE "(GET|<-- [0-9]{3}) https://[^ ]*v1/spots[^ ]*"
```

## 2. ⚠️ 시작 전 반드시 알아야 할 것 — `[STUB]` 은 정상이다

백엔드가 아직 햇살/야경을 모른다. 그래서 이 브랜치에는 임시 폴백이 들어가 있다
(`docs/PV-59/backend-compat-rollback.md`).

| 보이는 것 | 정상인가 |
|---|---|
| 햇살/야경 선택 시 이름이 `[STUB] …` 인 스팟 | ✅ 정상 — 서버에 데이터가 없어 가짜로 채운 것 |
| 노을/윤슬 선택 시 실제 스팟 사진과 이름 | ✅ 정상 — 실서버 응답 |
| 지도에서 노을+윤슬 동시 선택 시 필터가 안 걸린 듯한 마커 | ⚠️ **알려진 한계** — viewport 응답에 theme 필드가 없어 클라 필터 불가. 백엔드 완료 시 해소 |
| 어떤 조합에서든 `문제가 발생했어요. HTTP 400` | ❌ **버그** — NET-01 실패로 기록 |

## 6. 시나리오 — 네트워크 회귀 (필수)

### NET-01 — 어떤 무드 조합에서도 서버 오류가 없다

| | |
|---|---|
| **왜 필요한가** | 서버는 햇살/야경 값과 다중 `theme` 파라미터를 모른다. 잘못 내보내면 400이 뜬다. 화면만 봐서는 안 보이므로 로그로 확인해야 한다. |
| **절차** | 아래 스크립트로 지도·리스트 각각 16개 조합을 훑는다 |
| **기대결과** | ① `<-- 400` **0건**<br>② 나가는 요청의 `theme` 는 **없음 / `SUNSET` / `YUNSEUL`** 세 가지뿐<br>③ `SUNLIGHT`·`NIGHT` 가 붙은 요청 **0건**<br>④ `theme` 가 2번 붙은 요청 **0건** |
| **증적** | 아래 명령 출력 텍스트 (`PV59-NET-01-log.txt`) |

```bash
# 리스트 모드 무드 캡슐 x좌표(1080x2400 기준). 지도 모드는 X=(138 354 572 786), Y=290
X=(168 378 586 834); Y=340
GRAY=(0 1 3 2 6 7 5 4 12 13 15 14 10 11 9 8)   # 한 번에 한 개만 토글되는 순서
adb logcat -c
prev=0
for g in "${GRAY[@]}"; do
  d=$(( prev ^ g ))
  for b in 0 1 2 3; do
    (( d & (1<<b) )) && adb shell input tap ${X[$b]} $Y
  done
  prev=$g; sleep 3
done

echo "400 건수: $(adb logcat -d | grep -c '<-- 400')"          # 0 이어야 한다
adb logcat -d | grep -oE "GET https://[^ ]*v1/spots[^ ]*" \
  | grep -oE "theme=[A-Za-z]+" | sort | uniq -c                 # SUNSET/YUNSEUL 만 나와야 한다
```

> 좌표는 1080×2400(Pixel 8 / xhdpi) 기준이다. 다른 AVD면 `adb shell wm size` 로 확인 후 비례 조정한다.

## 8. 증적(스크린샷) 관리 규약

### 8.1 파일명

```
PV59-<시나리오ID>-<짧은설명>.png
예) PV59-EXP-03-multi.png
```

시나리오 ID를 파일명에 넣어야 판정표와 대조가 된다.

### 8.2 어디에 두나 — **PR 첨부가 기본, 저장소 커밋은 하지 않는다**

| 방식 | 판단 |
|---|---|
| **PR 본문에 드래그 앤 드롭 첨부** | ✅ **권장** |
| `docs/PV-59/screenshots/` 커밋 | ⚠️ 원칙적으로 지양 |
| Paparazzi 스냅샷 (`app/src/test/snapshots/images/`) | ✅ 이미 커밋됨 — 성격이 다름 |

**왜 커밋하지 않나.** 이 저장소가 PNG를 커밋하는 곳은 Paparazzi 스냅샷뿐인데,
그건 `./gradlew :app:verifyPaparazziDebug` 가 **매번 검증하기 때문에** 자격이 있다.
반면 에뮬레이터 스크린샷은 아무도 검증하지 않는다. 커밋해두면 UI가 바뀐 뒤에도
옛 이미지가 그대로 남아 **"이렇게 동작합니다"라고 거짓말하는 문서**가 된다.
PR 첨부는 그 PR 시점의 기록이라는 게 명확해서 이 문제가 없다.

굳이 저장소에 남겨야 한다면 `docs/PV-59/screenshots/` 에 두되,
`README` 에 **촬영 일자와 커밋 sha** 를 반드시 적어 "이 시점의 기록"임을 못박는다.

### 8.3 이미 커밋된 UI 증적 — Paparazzi

무드 캡슐/카드 배지의 **컴포넌트 단위 렌더**는 이미 스냅샷으로 고정돼 있다.
회귀가 나면 CI가 잡는다.

에뮬레이터 스크린샷이** 각각 책임진다. 두 증적의 역할이 다르므로 둘 다 필요하다.
