### 2-2. `GET /v1/spots/viewport`

### 2-3. 다중 전달 형태별 실측 (`GET /v1/spots`, 2026-08-16)

`SUNSET` + `YUNSEUL`을 동시에 걸어보려 한 모든 형태다. **동작하는 구성이 없다.**

| 형태 | 응답 | 판정 |
|---|---|---|
| `?theme=SUNSET&theme=YUNSEUL` (반복) | 200 · `{SS: 6}` | ❌ 둘째 값 무시 |
| `?theme=SUNSET,YUNSEUL` (CSV) | 400 `C002` | ❌ |
| `?theme[]=SUNSET&theme[]=YUNSEUL` | 400 | ❌ |
| `?themes=SUNSET,YUNSEUL` (복수형) | 200 · `{YS: 3, SS: 3}` | ⚠️ **미전달과 동일 — 필터 안 걸림** |
| `?theme=SUNSET` (단일, 비교용) | 200 · `{SS: 6}` | ✅ |
| (미전달) | 200 · `{YS: 3, SS: 3}` | 전체 |

> ⚠️ **판별 시 주의**: `themes=`(복수형)는 200에 두 테마가 섞여 나와서 성공처럼 보이지만,
> 결과가 미전달(전체 조회)과 완전히 같다. 서버가 모르는 파라미터를 무시한 것뿐이다.
> **지원 여부는 "결과가 전체보다 적으면서 두 테마가 섞여 있는가"로 판별해야 한다.**

### 재현 명령

```bash
B="https://pickflow-api.us/api/v1/spots?page=0&sort=RECOMMENDED"
curl -s "$B&theme=NIGHT_VIEW"                   # 400 C002
curl -s "$B&theme=SUNSET&theme=YUNSEUL" | python3 -c \
  'import sys,json,collections;d=json.load(sys.stdin);print(collections.Counter(s["theme"] for s in d["data"]["spots"]))'
# → Counter({'SS': 6})  ... YS 가 하나도 없음 = 둘째 값 무시
```

## 3. 요청 항목

### 🟢 완료 1 — 신규 테마 2종 (개발 배포 확인, 운영만 남음)

개발 서버에서 `SUNLIGHT`(→`SL` 6건), `NIGHT_VIEW`(→`NV` 2건) 모두 정상 응답을 확인했습니다.
클라이언트 debug 빌드는 이미 실데이터로 동작합니다.

**남은 것은 운영 반영뿐입니다.** 운영에서는 아직 400 `C002`가 납니다.
release 빌드가 나가기 전에 반영돼야 하며, **배포 일정만 알려주시면** 됩니다.

### 🔴 필수 2 — `theme` 다중 전달 지원

현재 `theme`는 단일 `string`이라 2개 이상 보내면 **첫 값만 적용되고 나머지는 버려집니다.**
400이 아니라 200이 오기 때문에 클라이언트가 오작동을 감지할 수 없습니다.

**요청**: `theme`를 복수로 받아 **OR 조건(합집합)** 으로 필터해 주세요.

```
GET /v1/spots?page=0&theme=SUNSET&theme=YUNSEUL&sort=RECOMMENDED
  → 노을 스팟과 윤슬 스팟이 모두 섞여서 반환

GET /v1/spots/viewport?...&theme=SUNLIGHT&theme=NIGHT_VIEW
  → 햇살 마커와 야경 마커가 모두 반환
```

- 형식은 **반복 파라미터**(`?theme=A&theme=B`)를 선호합니다. Retrofit이 `List<String>`을
  그대로 직렬화하므로 클라이언트 변경이 없습니다.
- CSV(`?theme=A,B`)도 무방하나 **어느 쪽인지 확정**해 주세요. 현재 CSV는 400입니다.
- 미전달 시 전체 조회는 **현행 유지**입니다(변경 불필요).

> **왜 클라이언트에서 못 거르나**: 리스트가 6건씩 페이징되기 때문입니다.
> 전체를 받아 클라이언트가 거르면 한 페이지가 통째로 걸러져 "결과 없음" 화면이 나오고,
> 페이지당 표시 건수가 들쭉날쭉해집니다. viewport는 응답에 `theme`이 없어 아예 불가능합니다.

### 🟡 권장 3 — viewport 응답에 `theme` 추가

`/v1/spots/viewport` 응답(`spots[]`)에 `theme` 필드를 넣어 주세요.

현재 없어서 **서버가 다중 필터를 못 해줄 때 클라이언트가 대신 거를 수조차 없습니다.**
필수 2가 어렵다면 이것만이라도 있으면 임시 대응이 가능합니다.

### 🟢 완료 4 — 응답 `theme`의 2글자 코드 (확인됨)

개발 서버 실응답으로 확인했습니다. **추가 조치 불필요**하며, 참고용으로 남깁니다.
요청은 풀네임(`SUNSET`), 응답은 2글자 코드(`"SS"`)라는 비대칭이 있습니다.

| 테마 | 요청값 | 응답 코드 |
|---|---|---|
| 노을 | `SUNSET` | `SS` |
| 윤슬 | `YUNSEUL` | `YS` |
| 햇살 | `SUNLIGHT` | `SL` ✅ |
| 야경 | `NIGHT_VIEW` | `NV` ✅ |

(장기적으로 요청/응답을 풀네임으로 통일하면 더 좋겠지만 급하지 않습니다.)

### ⚪ 참고 5 — 리스트 응답에 좌표가 없습니다

`GET /v1/spots` 응답에 `latitude`/`longitude`가 없습니다.
그런데 **지도 최초 진입이 이 엔드포인트를 씁니다**(viewport 영역이 아직 없어서).
그래서 지도 첫 프레임의 마커 좌표가 (0, 0)으로 만들어집니다.

첫 카메라 정착이 곧바로 viewport 응답으로 덮어써서 실사용에선 드러나지 않지만,
구조적으로는 잘못된 데이터입니다. 클라이언트에서 고칠 수도 있어(지도 최초 로드도
viewport를 쓰도록 변경) **급한 요청은 아닙니다.** 참고만 부탁드립니다.

## 5-B. BE PR #162 확인 결과 (2026-08-18)

반복 파라미터 형식은 **저희 구현과 일치**합니다. 클라이언트 변경이 필요 없습니다.

| 항목 | PR #162 | 안드로이드 |
|---|---|---|
| 파라미터 이름 | `theme` (단수, 반복) | `@Query("theme")` ✅ |
| 전달 형식 | 반복 파라미터 | Retrofit `List<String>` ✅ |
| 빈 값 | `null`/빈 리스트 = 필터 없음 | 빈 Set → 파라미터 미부착 ✅ |
| 대상 | `/v1/spots` + `/v1/spots/viewport` | 양쪽 다 대응 ✅ |

### ⚠️ 다만 Swagger 예시가 틀렸습니다 — **백엔드 확인 완료(2026-08-19)**

> 백엔드에 확인한 결과 **다중 전달도 요청값은 풀네임**이라고 회신받았다.
> 즉 `?theme=SUNSET&theme=YUNSEUL` 이 맞고, Swagger 의 `?theme=SS&theme=YS` 예시가
> 잘못된 것이다. **안드로이드는 이미 풀네임으로 보내고 있어 변경 사항이 없다.**
> 남은 것은 Swagger 문구 수정뿐이며, 다른 클라이언트(iOS)가 오해하지 않도록 필요하다.


PR 본문과 **Swagger `@Parameter` 설명**에 `?theme=SS&theme=YS` 로 적혀 있는데,
컨트롤러가 `@RequestParam List<SpotTheme> theme` 이라 Spring 이 **enum 상수명**으로 바인딩합니다.
`SS`/`YS` 는 `SpotTheme.getCode()` 가 만드는 DB 코드입니다.

```
?theme=SUNSET  → 200
?theme=SS      → 400 C002   (개발·운영 동일)
```

Swagger 를 그대로 보고 구현하는 다른 클라이언트(iOS)가 전부 400을 맞게 됩니다.
설명을 `?theme=SUNSET&theme=YUNSEUL` 로 고쳐달라고 요청해야 합니다.
