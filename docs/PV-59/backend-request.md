# [PV-59] 백엔드 요청서 — 무드 필터 확장 (햇살/야경 + 다중선택)

**작성** 2026-08-16 · **실측 대상** `https://pickflow-api.us/api` (운영)
**참조** API 문서 *유저 스팟 공개 시스템 (2026.08.14)* — `docs/PV-59/api-spec.html`

---

## 0. 한 줄 요약

무드 필터를 4종·다중선택으로 확장했는데, **(1) 신규 2종이 운영에 아직 없고 (2) 다중 전달을 서버가 받지 않습니다.**
`GET /v1/spots` 와 `GET /v1/spots/viewport` **두 엔드포인트 모두** 필요합니다.

---

## 1. 요청 대상 엔드포인트

| # | 엔드포인트 | 쓰는 화면 | 필요한 것 |
|---|---|---|---|
| 1 | `GET /v1/spots` | 탐색 리스트 + **지도 최초 진입** | 신규 2종 배포 · `theme` 다중 |
| 2 | `GET /v1/spots/viewport` | 지도 (카메라 이동 이후) | 신규 2종 배포 · `theme` 다중 · **응답에 `theme` 추가** |

> 지도가 두 엔드포인트를 씁니다. `lastViewport`가 정해지기 전(최초 진입)에는 `/v1/spots`,
> 첫 카메라 정착 이후에는 `/v1/spots/viewport`입니다.
> **한쪽만 지원되면 지도와 리스트의 필터 결과가 어긋납니다.**

---

## 2. 실측 결과 (2026-08-16, 운영)

### 2-1. `GET /v1/spots`

| 요청 | 응답 | 판정 |
|---|---|---|
| `?theme=SUNSET` | 200 · SS 6건 | ✅ |
| `?theme=YUNSEUL` | 200 · YS 6건 | ✅ |
| `?theme=SUNLIGHT` | **400 `C002`** 요청 타입이 올바르지 않습니다 | ❌ 문서엔 있는데 운영엔 없음 |
| `?theme=NIGHT_VIEW` | **400 `C002`** | ❌ 〃 |
| `?theme=SUNSET&theme=YUNSEUL` | **200 · SS 6건** | ⚠️ **둘째 값이 조용히 무시됨** |
| (미전달) | 200 · SS 3 + YS 3 | ✅ 전체 조회 |

### 2-2. `GET /v1/spots/viewport`

| 요청 | 응답 | 판정 |
|---|---|---|
| (미전달) | 200 · 36건 | ✅ |
| `?theme=SUNSET` | 200 · 15건 | ✅ |
| `?theme=NIGHT_VIEW` | **400 `C002`** | ❌ |
| `?theme=SUNSET&theme=YUNSEUL` | **200 · 15건** (SUNSET 단독과 동일) | ⚠️ 둘째 값 무시 |

응답 필드: `spotId`, `spotImageUrl`, `latitude`, `longitude`, `isMySpot` — **`theme` 없음.**

### 재현 명령

```bash
B="https://pickflow-api.us/api/v1/spots?page=0&sort=RECOMMENDED"
curl -s "$B&theme=NIGHT_VIEW"                   # 400 C002
curl -s "$B&theme=SUNSET&theme=YUNSEUL" | python3 -c \
  'import sys,json,collections;d=json.load(sys.stdin);print(collections.Counter(s["theme"] for s in d["data"]["spots"]))'
# → Counter({'SS': 6})  ... YS 가 하나도 없음 = 둘째 값 무시
```

## 3. 요청 항목

### 🔴 필수 1 — 신규 테마 2종 운영 반영

문서(2026.08.14)에는 `SUNLIGHT`(햇살) / `NIGHT_VIEW`(야경)가 정의돼 있으나
**운영에서는 400이 납니다.** 브랜치 `2026/HJY/유저스팟_공개시스템_개발`가
아직 배포되지 않은 것으로 보입니다.

- 두 엔드포인트 모두 신규 2종을 수용해야 합니다.
- **배포 일정을 알려주시면** 클라이언트의 임시 stub을 그 시점에 걷어내겠습니다.

### 🔴 필수 2 — `theme` 다중 전달 지원

현재 `theme`는 단일 `string`이라 2개 이상 보내면 **첫 값만 적용되고 나머지는 버려집니다.**
400이 아니라 200이 오기 때문에 클라이언트가 오작동을 감지할 수 없습니다.

**요청**: `theme`를 복수로 받아 **OR 조건(합집합)** 으로 필터해 주세요.

```
GET /v1/spots?page=0&theme=SUNSET&theme=YUNSEUL&sort=RECOMMENDED
  → 노을 스팟과 윤슬 스팟이 모두 섞여서 반환

GET /v1/spots/viewport?...&theme=SUNLIGHT&theme=NIGHT_VIEW
  → 햇살 마커와 야경 마커가 모두 반환
```

- 형식은 **반복 파라미터**(`?theme=A&theme=B`)를 선호합니다. Retrofit이 `List<String>`을
  그대로 직렬화하므로 클라이언트 변경이 없습니다.
- CSV(`?theme=A,B`)도 무방하나 **어느 쪽인지 확정**해 주세요. 현재 CSV는 400입니다.
- 미전달 시 전체 조회는 **현행 유지**입니다(변경 불필요).

> **왜 클라이언트에서 못 거르나**: 리스트가 6건씩 페이징되기 때문입니다.
> 전체를 받아 클라이언트가 거르면 한 페이지가 통째로 걸러져 "결과 없음" 화면이 나오고,
> 페이지당 표시 건수가 들쭉날쭉해집니다. viewport는 응답에 `theme`이 없어 아예 불가능합니다.

### 🟡 권장 3 — viewport 응답에 `theme` 추가

`/v1/spots/viewport` 응답(`spots[]`)에 `theme` 필드를 넣어 주세요.

현재 없어서 **서버가 다중 필터를 못 해줄 때 클라이언트가 대신 거를 수조차 없습니다.**
필수 2가 어렵다면 이것만이라도 있으면 임시 대응이 가능합니다.

### 🟡 권장 4 — 응답 `theme`의 2글자 코드 확정

요청 파라미터는 풀네임(`SUNSET`)인데 **응답은 2글자 코드(`"SS"`)** 로 내려옵니다.
신규 2종의 코드가 문서에 없습니다.

| 테마 | 요청값 | 응답 코드 |
|---|---|---|
| 노을 | `SUNSET` | `SS` |
| 윤슬 | `YUNSEUL` | `YS` |
| 햇살 | `SUNLIGHT` | **`SL`?** |
| 야경 | `NIGHT_VIEW` | **`NV`?** |

현재 `SL`/`NV`로 추정해 파싱하고 있습니다. 확정 값을 알려주시거나,
요청/응답을 풀네임으로 통일해 주셔도 좋습니다.

### ⚪ 참고 5 — 리스트 응답에 좌표가 없습니다

`GET /v1/spots` 응답에 `latitude`/`longitude`가 없습니다.
그런데 **지도 최초 진입이 이 엔드포인트를 씁니다**(viewport 영역이 아직 없어서).
그래서 지도 첫 프레임의 마커 좌표가 (0, 0)으로 만들어집니다.

첫 카메라 정착이 곧바로 viewport 응답으로 덮어써서 실사용에선 드러나지 않지만,
구조적으로는 잘못된 데이터입니다. 클라이언트에서 고칠 수도 있어(지도 최초 로드도
viewport를 쓰도록 변경) **급한 요청은 아닙니다.** 참고만 부탁드립니다.

## 4. 우선순위 · 클라이언트 영향

| # | 항목 | 우선순위 | 없으면 |
|---|---|---|---|
| 1 | 신규 2종 운영 반영 | 🔴 필수 | 햇살/야경이 가짜 데이터(`[STUB]`)로만 보임 |
| 2 | `theme` 다중 전달 | 🔴 필수 | 다중선택이 클라 필터로만 동작 → 빈 화면 발생 |
| 3 | viewport 응답 `theme` | 🟡 권장 | 지도에서 무드 2개 선택 시 필터가 안 걸림 |
| 4 | 2글자 코드 확정 | 🟡 권장 | 잘못 파싱하면 무드 배지가 전부 "노을"로 표시 |
| 5 | 리스트 좌표 | ⚪ 참고 | 지도 첫 프레임 마커 좌표 (0,0) — 클라 우회 가능 |

1·2·3이 완료되면 클라이언트의 임시 호환 계층을 제거합니다(`backend-compat-rollback.md`).

## 5. 그대로 보내는 메시지 (Slack / Jira 코멘트용)

> 안녕하세요, PV-59 무드 필터 확장(햇살/야경 추가 + 다중선택) 관련해서 백엔드 요청드립니다.
>
> **1. 신규 테마 2종이 운영에 아직 없습니다 (필수)**
> API 문서(2026.08.14)에는 `SUNLIGHT`(햇살), `NIGHT_VIEW`(야경)가 정의돼 있는데,
> 운영(`pickflow-api.us`)에 요청하면 400 `C002`가 옵니다.
> `2026/HJY/유저스팟_공개시스템_개발` 브랜치 배포 일정을 알려주실 수 있을까요?
> ```
> GET /api/v1/spots?page=0&theme=SUNLIGHT   → 400 C002
> GET /api/v1/spots?page=0&theme=NIGHT_VIEW → 400 C002
> ```
>
> **2. `theme` 다중 전달을 지원해 주세요 (필수)**
> 기획상 무드를 여러 개 동시에 선택할 수 있어야 하는데, 현재 `theme`가 단일 `string`이라
> 2개를 보내면 **첫 값만 적용되고 둘째는 조용히 버려집니다.** 400이 아니라 200이 와서
> 클라이언트가 오작동을 감지할 수 없는 게 특히 문제입니다.
> ```
> GET /api/v1/spots?page=0&theme=SUNSET&theme=YUNSEUL
>   → 200 이지만 SS 6건만 (YS 0건) = SUNSET 단독 결과와 동일
> ```
> `theme`를 복수로 받아 **OR 조건(합집합)** 으로 필터해 주시면 됩니다.
> 형식은 반복 파라미터(`?theme=A&theme=B`)가 클라이언트 입장에서 가장 편한데,
> CSV(`?theme=A,B`)여도 괜찮습니다. 어느 쪽으로 하실지만 알려주세요. (현재 CSV는 400입니다)
>
> ⚠️ **`/v1/spots` 와 `/v1/spots/viewport` 둘 다 필요합니다.**
> 지도는 최초 진입 시 `/v1/spots`, 카메라 이동 이후에는 `/v1/spots/viewport`를 쓰기 때문에
> 한쪽만 지원되면 지도와 리스트의 필터 결과가 서로 어긋납니다.
>
> **3. viewport 응답에 `theme` 필드를 넣어주실 수 있을까요 (권장)**
> `/v1/spots/viewport` 응답에 `theme`이 없어서, 서버가 다중 필터를 못 해줄 때
> 클라이언트가 대신 거를 수조차 없습니다. 2번이 어려우면 이것만이라도 있으면
> 임시로 대응할 수 있습니다.
>
> **4. 응답 `theme`의 2글자 코드를 알려주세요 (권장)**
> 요청은 풀네임(`SUNSET`)인데 응답은 2글자 코드(`"SS"`)로 오더라고요.
> 신규 2종은 각각 `SL`, `NV`가 맞을까요? 지금은 추정으로 파싱하고 있습니다.
> (요청/응답을 풀네임으로 통일해 주셔도 좋습니다)
>
> ---
> 위 1·2·3이 되면 클라이언트에 넣어둔 임시 호환 코드를 제거하겠습니다.
> 그 전까지는 햇살/야경이 `[STUB]` 접두사가 붙은 더미 데이터로 표시되고,
> 다중선택은 클라이언트 필터링으로만 동작합니다. QA 시 참고 부탁드립니다.
