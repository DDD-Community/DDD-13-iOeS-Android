# PV-41 — 구현 순서와 테스트 계획

## 구현 순서

### 1. 도메인과 Stub Backend

1. 도메인 모델에 다섯 상태와 출처·반려·추천·북마크·검수 결과를 정의한다.
2. Service 인터페이스를 UI 요구사항 기준으로 정의한다.
3. 공유 `StubSpotBackend`와 Stub Service를 `@Singleton`으로 구현한다.
4. 성공·실패·지연·경합 fixture와 각 상태의 초기 데이터를 추가한다.

### 2. 작성자 상태 전환

1. 상세 ViewModel의 의존성 책임을 정리한다.
2. 페이크도어와 `notifyUpdateRequested()`를 제거한다.
3. 신청·철회·반려 철회·오픈 취소·삭제를 구현한다.
4. 확인 모달, 실패 토스트, 동시 처리 새로고침을 구현한다.

### 3. 반려 수정·재신청

1. 편집 상세로 등록 폼을 프리필한다.
2. 기존 이미지 유지와 교체를 분리한다.
3. 재신청 모달과 `RE_REVIEW_PENDING` 전환을 구현한다.

### 4. 공개 경험

1. 출처와 추천 상태를 공개 상세에 연결한다.
2. 추천·취소, 로그인 가드, 중복 탭 방지, 실패 롤백을 구현한다.
3. 공개 유저 스팟을 공용 지도·리스트·클러스터에 포함한다.

### 5. 보관함과 결과 알림

1. 비공개 북마크 카드와 단일 삭제 안내를 구현한다.
2. 보관 탭 인디케이터와 승인·반려 스낵바를 구현한다.
3. 승인 후 첫 상세 진입 모달을 구현한다.

### 6. API 명세 반영과 Integration

1. 각 기능 문서의 API 계약 입력란을 서버 명세로 채운다.
2. DTO·Retrofit API·Mapper·`Default*Service`를 작성한다.
3. Stub 응답 fixture를 실제 response fixture로 교체·확장한다.
4. `ServiceModule` 바인딩을 Stub에서 Default 구현으로 전환한다.
5. 서버 개발 환경에서 정상·오류·경합 응답을 검증한다.
6. ViewModel과 Compose UI에 연동 전용 분기가 추가되지 않았는지 확인한다.

## Stub 단계 완료 기준

- 서버 없이 등록 → 신청 → 승인/반려 → 재신청/오픈 취소 전체 흐름을 재현할 수 있다.
- 상태 변경이 상세, 지도, 리스트, 보관함에 일관되게 반영된다.
- 추천과 비공개 북마크가 공유 인메모리 상태를 사용한다.
- 네트워크 지연에 대응하는 로딩·중복 탭 방지 UI를 확인할 수 있다.
- 일반 실패와 철회/검수 경합 UI를 개발 메뉴 또는 테스트 fixture로 재현할 수 있다.
- ViewModel 테스트에서 Stub Service 대신 Mock Service도 주입할 수 있다.

## Integration 단계 완료 기준

- 모든 기능 문서의 API 계약 상태가 `VERIFIED`다.
- 실제 response fixture의 DTO·Mapper 테스트가 존재한다.
- Stub과 Default Service가 같은 도메인 결과와 오류 의미를 제공한다.
- Hilt 바인딩 전환 외에 ViewModel·UI 변경이 없다.
- 서버 개발 환경에서 상태 전이, 추천 최종 수, 비공개 북마크, 결과 확인을 검증한다.
- 서버 미지원 필드나 임시 fallback이 남으면 코드와 문서에 제거 조건을 기록한다.

## Phase A — ViewModel·서비스

- 등록 결과가 `DRAFT`로 매핑된다.
- 다섯 상태가 손실 없이 매핑된다.
- 신청·철회·재신청·오픈 취소 성공 시 서버 최종 상태를 반영한다.
- 실패 시 이전 상태와 버튼 활성 상태를 복구한다.
- 철회/검수 경합 시 안내 후 최신 상세를 조회한다.
- 추천 성공 시 서버 최종 카운트를 사용하고 실패 시 롤백한다.
- 연속 추천 탭이 한 요청으로 제한된다.
- 비로그인 추천은 서버 요청 없이 로그인 유도 상태를 발생시킨다.
- 비공개 북마크 삭제 실패 시 카드가 원래 위치에 복구된다.
- 검수 결과 확인 전후 인디케이터가 올바르게 바뀐다.

## Phase B — Compose UI

- 상태별 CTA가 명세와 일치한다.
- 모달 카피와 확정·보조 버튼 동작이 일치한다.
- 반려 사유와 두 액션이 표시된다.
- 재신청 폼에 기존 값이 채워지고 작성 중 값이 유지된다.
- 공개 상세에만 추천과 피드백이 표시된다.
- 큐레이션 출처와 유저 등록 뱃지가 구분된다.
- 비공개 북마크는 상세 대신 단일 삭제 안내를 연다.
- 보관 탭 인디케이터, 결과 스낵바, 승인 완료 모달이 동작한다.

## Phase C — Paparazzi·지도

- `DRAFT`, 검수중, 반려, 공개, 큐레이션 상세
- 반려 배너와 신청·철회·재신청·오픈 취소·삭제 모달
- 추천 활성·비활성과 긴 숫자 카운트
- 비공개 북마크 카드와 보관 탭 인디케이터
- 회색 MY 핀, 일반 공개 핀, 선택 주황 링, 혼합 클러스터
- 라이트·다크와 주요 접근성 폰트 크기
